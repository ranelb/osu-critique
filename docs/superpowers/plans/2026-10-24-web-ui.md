# Web UI + per-map index — plan (2026-10-24)

A local web frontend over the analysis corpus, per-map showcase pages, human
annotations the LLM critic can read, and an opt-in ingest digest. The design
was settled in an interview; this file is the frozen record of those decisions.

**The server is a second frontend, not the product.** Every number it renders
comes from `osu_critique.*` — the same code `analyze`, `report`, `attempts` and
`coach` run. No analysis logic is duplicated in the web layer, and the CLI
remains the only thing that *creates* data.

Status: plan. Prior state `0.11.0` (tagged at the commit that added this file).

---

## Decisions

| Branch | Decision |
|---|---|
| Audience | One player (the author) plus anyone who clones the repo. No accounts, no multi-user, no public deployment. |
| Frontend role | Second frontend over the library. CLI stays authoritative. |
| Persistence | SQLite at `out/index.sqlite`, a **projection** of `out/*_metrics.json`, never a second source of truth. |
| Per-object rows | Not in v1. `objects` is designed as an additive table later. |
| Map metadata | Parsed from the `.osu` at index time: `Title/TitleUnicode/Artist/ArtistUnicode/Creator/Version/Source/Tags/BeatmapID/BeatmapSetID` + the `[Events]` background filename. |
| Covers | Lazy `GET` from `assets.ppy.sh/beatmaps/<setid>/covers/{card,cover}@2x.jpg`, cached on disk, offline text fallback. No osu! API call required. |
| Visual language | osu!-listing *layout and palette* (dark, `#ff66aa`, cover card grid, star pill, rounded corners, heavy geometric sans) with an **open** font. Torus is explicitly not redistributable (`osu-resources/.../Fonts/Torus/LICENCE`: "requires a commercial licence for distribution"). Text mod pills, no osu! logo, "not affiliated with ppy" footer. |
| Annotations | `{scope: "map"|"run", t_map?, body, tags, created_at}`. Textbox above the run view; a timestamp button stamps the playhead as **map time** (chip `02:14.312`); no timestamp = a general comment. Map notes are shared by all attempts; run notes belong to one attempt. |
| Annotation storage | Canonical sidecar `out/annotations/<beatmap_md5>.json` (one file per map, both scopes inside), indexed into SQLite. Human-editable, backup-able, agent-editable. |
| Critique storage | Canonical `out/critiques/<replay_md5>.json` with `{model, prompt_hash, run_hash, created, body}`. Deterministic reports are computed live; LLM critiques are stored and marked stale when `run_hash` changes. |
| Web stack | FastAPI + uvicorn + Jinja2 + htmx as the optional extra `osu-critique[web]`. Charts are inline SVG/canvas built client-side from the objects JSON; matplotlib never runs in a request. |
| Bind | `0.0.0.0:8765` by default, no auth. **Recorded risk**: any LAN device can read the history and spend the LLM key. `web.llm_remote` exists and defaults to `true` (the owner's explicit choice); set it to `false` to 403 the LLM routes. |
| Export | Opt-in, `export.enabled: false`, all statuses by default (toggleable). BeatmapExporter (MIT) is vendored in our releases for linux-x64/win-x64/osx-arm64 with pinned sha256; fall back to detection, then to watch-only. **The tool never schedules itself** — docs carry systemd/Task Scheduler snippets. |
| Digest | Mechanical ingest + a deterministic digest whenever export is on; an LLM critique only on request. Output: web feed + `out/digests/YYYY-MM-DD.md`. |
| Renderer seam | No playback in v1, kept open: `replay_path`/`map_path` are indexed, `/run/{id}/frames` is a reserved route, the run page reserves a `<div id="stage">`, and nothing assumes objects are the finest granularity. A future renderer reads `.osr` frames server-side. |
| Done | The 160 existing tests pass without `[web]`; index tests incl. missing objects; route smoke tests via `TestClient`; a golden map-page snapshot; Playwright opens the pages, screenshots them and reports. Then human-in-the-loop refinement — there is no hard done line. |

### Non-goals (for now)

No replay playback/cursor animation, no auth or multi-user, no public hosting
instructions, no re-analysis from the web (new replays arrive via export, old
ones via the CLI), no global osu! leaderboards, no mobile-specific layout, no
websockets/live updates. Playback is the one of these that is likely to move;
it is written down in `docs/ROADMAP.md` as "not now", not as "never".

## Data model

`out/` artifacts stay canonical. `index.sqlite` is derived and may be deleted at
any time — **except** that annotations and critiques are canonical files under
`out/` and are re-read into the index, so deleting the DB loses nothing.

```sql
-- one row per analysed replay; a projection, not a copy of the metrics doc
CREATE TABLE runs (
  replay_md5      TEXT PRIMARY KEY,
  tag             TEXT,
  beatmap_md5     TEXT NOT NULL,
  player          TEXT,
  played_at       TEXT,
  map_name        TEXT,
  mod_string      TEXT,
  mods_json       TEXT,
  time_scale      REAL,
  od REAL, ar REAL, cs REAL, hp REAL,
  n_objects       INTEGER,
  n_objects_map   INTEGER,
  accuracy        REAL,
  max_combo       INTEGER,
  full_combo      INTEGER,
  ur              REAL,
  ur_pct_of_300   REAL,
  hit_error_mean  REAL,
  hit_error_std   REAL,
  whiffed_presses INTEGER,
  counts_recorded_json TEXT,
  counts_detected_json TEXT,
  trust_ok        INTEGER,       -- trust.trustworthy
  trust_delta     INTEGER,       -- trust.abs_delta_total
  failed          INTEGER,
  is_relax        INTEGER,
  time_base_overridden INTEGER,
  sr              REAL,          -- joined from stars_by_md5.json when present
  pp              REAL,          -- joined from pp_by_replay.json when present
  rank_status     TEXT,          -- joined from beatmap_status.json when present
  json_path       TEXT,          -- absolute path to the metrics JSON
  objects_path    TEXT,
  objects_missing INTEGER,       -- analysed with --no-objects
  replay_path     TEXT,          -- for a future renderer; may be NULL
  map_path        TEXT,
  mtime           REAL,
  indexed_at      TEXT
);

CREATE TABLE beatmaps (
  beatmap_md5   TEXT PRIMARY KEY,
  beatmap_id    INTEGER,
  set_id        INTEGER,
  title         TEXT,
  title_unicode TEXT,
  artist        TEXT,
  artist_unicode TEXT,
  creator       TEXT,
  version       TEXT,
  source        TEXT,
  tags          TEXT,
  background    TEXT,            -- filename from [Events]
  cover_path    TEXT,            -- cached cover on disk, NULL until fetched
  cover_fetched_at TEXT,
  metadata_missing INTEGER       -- .osu absent or unparsable
);

CREATE TABLE annotations (
  id          INTEGER PRIMARY KEY,
  scope       TEXT NOT NULL CHECK (scope IN ('map','run')),
  beatmap_md5 TEXT NOT NULL,
  replay_md5  TEXT,              -- NOT NULL when scope = 'run'
  t_map       REAL,              -- NULL = general comment
  body        TEXT NOT NULL,
  tags        TEXT,              -- comma-separated
  created_at  TEXT NOT NULL,
  updated_at  TEXT
);

CREATE TABLE critiques (
  replay_md5  TEXT PRIMARY KEY,
  model       TEXT NOT NULL,
  prompt_hash TEXT NOT NULL,
  run_hash    TEXT NOT NULL,
  created     TEXT NOT NULL,
  body        TEXT NOT NULL
);
```

Derived index the pages need: `(beatmap_md5, played_at)` for a map's attempt
list, `(played_at)` for the feed, `(accuracy)` for sorting.

**Time base.** `t_map` is stored in map time. On save, convert from the run's
calibrated base with the existing `time_base.rows_to_player` / `mod_scale`
plumbing (`profile.py` has the accessors); on display, convert back. A note
whose timestamp cannot be converted is refused loudly rather than stored wrong.

**Joins.** `stars`/`pp`/`status` come from the existing caches in `out/`
(`stars_by_md5.json`, `pp_by_replay.json`, `beatmap_status.json`), joined at
index time. Missing cache = NULL, never an error.

## Module layout

```
src/osu_critique/
  index.py         # schema, open(), build(), sweep(), upsert_run(), drift()
  mapmeta.py       # [Metadata] + [Events] parser for .osu (no new deps)
  annotations.py   # canonical sidecar read/write, time-base conversion, validation
  critiques.py     # canonical store, run_hash/prompt_hash, staleness
  covers.py        # lazy assets.ppy.sh fetch + disk cache + offline fallback
  export.py        # BeatmapExporter detect / vendored download / run / watch mode
  digest.py        # deterministic per-day digest over new runs
  web/
    __init__.py
    app.py         # create_app(): routes + templates + static
    views.py       # page handlers (list, map, run)
    api.py         # JSON routes: objects, critique, annotations, export status
    templates/     # Jinja: base, index, map, run, partials
    static/        # css, htmx.min.js, fonts/*.woff2, app.js (charts)
```

New CLI subcommands (all on the same `argparse` front end):

```sh
osu-critique index [--rebuild] [--check] [--json]
osu-critique serve [--host 0.0.0.0] [--port 8765] [--no-index]
osu-critique annotate add --map <md5> [--run <md5>] [--t 134.312] <text>
osu-critique annotate list [--map <md5>] [--json]
osu-critique annotate rm <id>
osu-critique export [--install] [--run] [--status ranked,loved,...] [--watch]
osu-critique digest [--date YYYY-MM-DD] [--json]
```

`analyze` and `batch` upsert their run row as they write the JSON, so the index
is never behind a run the CLI just produced.

## Milestones

Each tag is a working, installable state. Acceptance is the bar; a milestone is
not done because the code exists.

### 0.12.0 — the index

- `index.py`, `mapmeta.py`, `index --rebuild/--check/--json`, upsert from
  `analyze`/`batch`.
- Acceptance: cold build over the ~3 171-run corpus in **< 120 s**; a no-op
  incremental sweep in **< 2 s**; every row in `runs` resolves to its JSON on
  disk; `beatmaps` populated from the paired `.osu` with `set_id`; a missing
  `.osu` yields `metadata_missing = 1`, not a crash; a run without
  `_objects.json` yields `objects_missing = 1`; `--check` reports drift
  (new/deleted/changed files) without writing.
- Tests: build from `tests/fixtures`, incremental add, rebuild, missing
  objects, unknown `schema_version`, drift check, md5 that appears twice.

### 0.13.0 — web read path

- `/` cover-card list (sort/filter: recency, accuracy, SR, status, attempt
  count), `/map/<md5>` (hero cover, map stats, attempt table, sparklines, the
  existing cross-attempt `attempts` block), `/run/<replay_md5>` (trust banner
  first, summary cards, charts, deterministic report, object table).
- JSON routes: `/api/objects/<replay_md5>`, `/api/map/<md5>`, `/api/runs`.
- Acceptance: all Q4 test rules; pages render with `[web]` absent? No — the
  package must still import and the CLI must run without `[web]`; `serve`
  prints one actionable line when the extra is missing.
- Playwright opens list/map/run, screenshots them into `docs/screenshots/`,
  and reports layout/console problems. Not in CI.

### 0.14.0 — annotations

- Sidecar + CLI + web textbox above the run view + timestamp chip + playhead
  scrubber (clicking an object row moves the playhead).
- Acceptance: a map note appears on every attempt of that map; a run note only
  on its own; a note saved on a `time_base.overridden` run round-trips to the
  same map position; `annotate` from the CLI and the browser write identical
  files; the coach prompt gains a notes block with the timestamps rendered in
  map time.

### 0.15.0 — critiques

- Deterministic report inline (already cheap); LLM button with stored critique,
  stale badge via `run_hash`, SSE streaming, key read server-side only.
- Acceptance: no key → button disabled with a reason; stored critique survives
  a DB delete; changing the run's metrics flips the badge to stale; `llm_remote:
  false` returns 403 for the LLM route only.

### 0.16.0 — export and digest

- `export` (install/detect/watch), `digest`, web feed, `out/digests/*.md`.
- Acceptance: with `export.enabled: false` nothing touches the Realm and the
  command says why; with it on, one run analyses only new replays and is
  idempotent on a second run; the digest names new runs, compares against the
  rolling baseline, and never calls an LLM.

### 0.20.0 — GUI complete

- Polish pass: cover caching and offline behaviour, open font + palette, empty
  states, keyboard navigation, `docs/web.md`, README screenshots, `[web]`
  install instructions, version bump. Whatever 0.17–0.19 turns up while using
  it lands here.

## Config

Extends `~/.config/osu-critique/config.json` (env override wins, as today):

```json
{
  "web": {
    "host": "0.0.0.0",
    "port": 8765,
    "index_on_boot": true,
    "llm_remote": true,
    "cover_cache": true
  },
  "export": {
    "enabled": false,
    "statuses": ["ranked", "qualified", "loved", "approved", "pending", "graveyard"],
    "binary": null
  },
  "llm": { "store_critiques": true }
}
```

Env: `OSU_WEB_HOST`, `OSU_WEB_PORT`, `OSU_EXPORT_ENABLED`, `OSU_EXPORT_BINARY`.
`osu-critique setup` gains a short web/export section; `osu-critique paths`
prints the index, cover cache and vendored binary locations.

Dependencies: `[web]` = `fastapi`, `uvicorn[standard]`, `jinja2`; htmx and the
font are vendored static files (no CDN, works offline). `[dev]` keeps pytest;
Playwright is an agent-side tool, not a project dependency. The core stays
`numpy` + `slider==0.8.4`.

## Risks

- **LAN + LLM key.** Any host on the network can spend the key and read the
  history. Accepted by the owner; `web.llm_remote: false` is the one-line
  mitigation, documented in `docs/web.md`.
- **`assets.ppy.sh` at runtime.** A third-party CDN is now in the map page's
  path. Mitigations: `card@2x` only for the grid, one request per map, a
  disk cache, an identifying user agent, no prefetching of the 793-map
  backfill, and a text-only card when offline.
- **Vendored BeatmapExporter.** MIT requires attribution: pin the version,
  record the source URL in `THIRD_PARTY.md`, verify sha256 on download, and
  keep the watch-only path working when the download fails.
- **The index is a projection.** Any feature that quietly reads the DB as truth
  will drift. `index --check` exists to make that visible; the run page always
  renders from the JSON artifact, not from the row.
- **`.osu` availability.** `tmp_maps/` is gitignored and maps can be deleted.
  Metadata is best-effort (`metadata_missing`), and the UI degrades to
  `map_name`.
- **0.11.0 is already released** (tag `v0.11.0` at `fe9befc`, GitHub release
  and wheel published 2026-10-10). `f51687f` (flatten API v2 statistics) is a
  post-tag fix on `main`; it ships with 0.12.0. There is nothing to re-tag.
