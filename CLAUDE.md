# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
pip install -e ".[dev]"          # install (add ".[charts]" for matplotlib)
pytest -q                        # full suite (~270; 45 need [web], 6 need real replays)
osu-critique index [--rebuild|--check]   # rebuild/refresh out/index.sqlite (derived)
osu-critique library scan [--rebuild] [--status] [--source DIR]   # features for every installed map
osu-critique recommend [--limit N] [--json]   # maps that train your current weaknesses
osu-critique serve               # local web frontend on :8765 (needs .[web]): dashboard at /, listing at /maps
osu-critique annotate add --map <md5> [--run <replay_md5>] [--t 2:14.312] "note"
osu-critique export [--install|--run]   # opt-in; needs export.enabled
osu-critique digest                     # ingest new replays + write the digest
pytest tests/test_judge.py -q    # one file
pytest tests/test_judge.py::test_name -q   # one test
osu-critique batch --charts      # pair + analyze every replay in replays/ and the osu! install
osu-critique analyze <replay.osr> <map.osu> [tag] [--charts]
osu-critique report out/<tag>_metrics.json   # deterministic critique, no keys
```

CI (`.github/workflows/test.yml`) runs `pytest -q` on Python 3.10, 3.12, 3.14. Releases run from tags via `.github/workflows/release.yml`.

## Architecture

The analysis core is fully local and deterministic; the LLM pieces are optional layers on top of its JSON output.

- **Pipeline** (`src/osu_critique/report.py: analyze`): parse `.osr`/`.osu` (via the pinned `slider==0.8.4` library) → sort frames by time → judge presses against objects → calibrate the time base → compute metrics → write `out/<tag>_metrics.json` and `out/<tag>_objects.json`. `docs/internals.md` has the step-by-step version. `io/replay.py: read_score_meta` also reads the lazer trailing score-info block (stdlib `lzma`/`json`): exact mod settings (`speed_change`), `online_id`, pauses, and per-category `statistics` / `maximum_statistics`; `report.slider_truth` compares the game's aggregate slider tails with the frame model.
- **Judgement** (`metrics/assignment.py: judge`) is the core invariant: objects are walked in time order, each takes the first press inside its mod-adjusted hit window whose cursor is on the circle, and presses are consumed once. Window and circle radius come from the mod-adjusted difficulty (`io/beatmap.py`). Changes here must be re-checked with `scripts/judge_drift.py` against the game's recorded counts (needs real replays).
- **Calibration**: the time scale tries `[player_scale, 1.0]` and keeps the lower weighted L1 over the whole count vector, not just misses. `player_scale` is `1 / speed_change` when the lazer score block carries a custom rate, else the DT/HT flag. Some lazer exports store frames in map-time while the score says otherwise; both clocks are reported in `metrics.time_base`.
- **Metrics** live in `src/osu_critique/metrics/`. Each block is a separate module that `report.py` assembles; `aim.py` (cursor arrival, relevant for Relax replays where taps are meaningless) and `autopsy.py` (miss shapes) are the largest. Tap-derived sections must report "unavailable" under Relax, not zero.
- **Tiers** are separate entry points over the same JSON: `report.py` (rule-based, offline), `coach.py` (one LLM call, DeepSeek V4 Flash by default, OpenAI-compatible), and `prompt` (framework + data for pasting into any AI). `profile.py` fetches osu! player stats (API v2, HTML scrape only with `--scrape` / `allow_scrape`).
- **Config and path discovery**: `config.py` resolves settings as env var (`OSU_*`) > config file > auto-detection > default. `io/pairing.py` finds replay↔map pairs across osu!lazer, osu!stable and the repo's `replays/` + `maps/`. `cli.py` is the `argparse` front end; `osu-critique paths` prints every resolved path.
- **Recommend** (`recommend.py`, `blacklist.py`, `docs/recommend.md`): `recommend` reads the runs + `library_beatmaps` and produces three deterministic bucket lists — `new`, `improver`, `maintain` — plus a skill profile. Weaknesses are band-corrected **miss-rate** residuals split at each material dimension's median; the unit is runs and the axis is map material (not per-object families), so the same features score a never-played map. No model, no timestamps: `recommend --json` must stay byte-equal between calls. Blacklist is `out/blacklist.json` (authored, mirrored into the `blacklist` table); a map played only in Relax is `relax_only`, never "new".
- **Library** (`library.py`, `docs/library.md`): `library scan` parses every `.osu` on disk (lazer store + `maps/` + `stable` Songs) into `library_beatmaps` — map-side features (SR via rosu-pp, BPM/length/AR/OD, spacing buckets, sustained runs, anti-flow share) for maps no replay touched. Derived, disposable, incremental by mtime; `library.FEATURE_VERSION` is the re-extraction trigger. Not swept on `serve` boot (150 s cold). The same `metrics` functions a play is judged with produce the features; there is no second detector.
- **Geometry** (`metrics/geometry.py`, `docs/geometry.md`): shapes of runs of objects (triangle/square/star/circle/arc/line/zigzag/shuttle/stack), a map property. Cycles + position fits, not corner angles; thresholds in one table; unlabelled is a valid, large answer. Not wired into the pipeline or `library` yet: `patterns.bucket` is still what the recommender reads. Check changes with `scripts/eval_patterns.py` and by eye with `scripts/render_patterns.py` on real maps; the synthetic fixtures alone cannot tell you the labels are right.
- **Index** (`index.py`, `mapmeta.py`, `docs/index.md`): `out/index.sqlite` is a **projection** of `out/*_metrics.json` for the web frontend — listing/filter scalars plus a `beatmaps` row parsed from the `.osu`. `analyze`/`batch` upsert; `index --rebuild`/`--check` are the maintenance commands. Heavy blocks and per-object records stay in the JSON.
- **Export/digest** (`export.py`, `digest.py`, `docs/export.md`): opt-in only (`export.enabled`), never self-scheduled. Drives BeatmapExporter's text menu (`status …` / `reset`) through a pty; the pinned sha256 lives in `export_assets.json` and the release workflow attaches the binaries. `digest` ingests `.osr` newer than `out/digests/.last` and writes a deterministic markdown summary — no model in that path, ever.
- **`app.js` is untested by the server suite** (`tests/test_web.py::test_app_js_defines_every_function_it_calls` is the only guard). 0.22.0 shipped with two functions sliced out of the file by a careless range edit: the page rendered fine and the playhead, boards and critique stream were dead. After editing it, check the browser console.
- **Rail** (`templates/partials/rail.html` + a `toc` list from `data.run_toc` / `map_toc` / the feed route): one anchor per block; counts only where a count is not already on the cards. `app.js:initRail` picks the last block above 28 % of the viewport on scroll/resize/toggle — deliberately not an IntersectionObserver, since folds move blocks without scrolling.
- **Folds**: `<details class="fold">` with a `.peek` line saying what is inside (rule, count, model+when), never a value the stat cards already show. `/run/<id>/report.txt` is the clipboard copy and later the critique-tab input: it serves `report_sections.to_text`, the same text the CLI prints.
- **Report** (`report_sections.py`): the deterministic critique as data (kv / note-with-tone / table); `cli.render_report` renders the same sections as text, so the CLI and the run page stay in sync. Keep it defensive: five stored runs have `legs: null`, empty `error_shape` and null stream velocities, and used to crash the report.
- **Scope** (`scope.py`, `docs/ask.md`): a selection (runs + maps + date range + optional question, additive, deduped) → **one deterministic text**. That text is the page's summary, the model's only input, and what the sidecar stores. The question sits at the top of it (`## The question`) and is therefore part of the hash. Do not add a second prompt path: the text is the contract. Sizing rules (`FULL_REPORT_LIMIT`, `MAP_TABLE_LIMIT`, `RUN_TABLE_LIMIT`, `MAX_TEXT_BYTES`) live at the top of the module; the header must always count what was omitted.
- **Answers** (`answers.py`, `docs/ask.md`): canonical `out/answers/<hash>.json` (legacy `out/critiques/scope/` is moved on first touch and still read). Metadata-only mirror in the `answers` table (schema v6). The hash covers the text **and** the system prompt, so a changed corpus, note or question is a different artifact — there is no stale state.
- **Per-run critiques** (`critiques.py`, `docs/ask.md`, legacy): canonical `out/critiques/<run_id>.json`, mirrored into the index. `run_hash` covers the metrics **and the notes**; `prompt_hash` covers the system prompt; a different model is not staleness. The web streams the call as SSE; the key never leaves the server; `web.llm_remote: false` gates non-loopback clients on the LLM routes only.
- **Annotations** (`annotations.py`, `docs/annotations.md`): canonical sidecars `out/annotations/<beatmap_md5>.json`, mirrored into the index on every sweep. `t_map` is **seconds in map time**; object `t` is row-clock milliseconds — convert with `time_base.rows_scale` (`to_map_time`/`to_row_ms`). `coach`/`prompt` read them; `report` does not. The web forms need `python-multipart`.
- **Boards** (`web/boards.py`, `docs/web.md`): per-run near-miss windows + playfield overview + cleanest stretch, computed from `autopsy.misses.rows` and the object positions, drawn client-side on canvas. Keep it out of the request path: the panel is a collapsed `<details>`.
- **Dashboard** (`dashboard.py`, `docs/web.md`): `/` renders `partials/dash/<id>.html` per enabled widget from `dashboard.WIDGETS`, in the order stored in `~/.config/osu-critique/dashboard.json` (unknown ids dropped, missing defaulted, player pin falls back to the most-run player). `dashboard.build` reuses `recommend.build` once for the profile + cards; the trend/calendar geometry is precomputed in Python so the page needs no JavaScript. `/maps` is the old listing; `/settings` is one form that writes the file and redirects (no JS, no re-post). `/blacklist` + `/blacklist/remove` are the × and the manager.
- **Glossary** (`web/glossary.py`, `partials/gloss.html`, `docs/web.md`): the site's wording has one home. `gloss(id, label)` renders a link whose `title` is the one-liner; `learn(id)` is the widget-header `?`; `/learn` renders all terms. `docs/` stays the formula authority and each entry links there. `tests/test_dashboard.py` asserts every `/learn#…` on `/` resolves to a real anchor.
- **Web** (`web/app.py`, `web/data.py`, `covers.py`, `docs/web.md`): FastAPI + Jinja2 + htmx, optional extra `[web]`. Second frontend only — it imports the library and reads the index, never recomputes a metric. Pages live in `web/templates/`, the whole client script is `web/static/app.js` (two canvases + one lazy table), and `tests/test_web.py` drives every route through `TestClient`.

## Conventions and traps

Read `docs/ROADMAP.md` before changing analysis code; it records the mistakes already made.

- `snap` is in **quarter-beats**: the divisor is `4 / snap`. Use `profile.divisor()` / `beats_label()`, and always print the real ms gap next to a label.
- Convert ms to the player's time base before quoting numbers for RX/Relax; keep `window_ms` explicit in output.
- Row indices are **object indices**, not filtered-row indices (an earlier autopsy bug mis-mapped rows this way).
- Legs shorter than ~1.5 circle radii have no meaningful direction; filter on the gap in radii, not pixels.
- Population gates scale with map size: `min(20, max(8, 3% of objects))`. Never state a rate from n<10, and quote n with every rate.
- Findings should come from contrasts (same map across attempts, shapes with corners vs without), not absolute numbers.
- New features need new fixtures in `tests/fixtures/`. Synthetic fixtures are regenerated by `scripts/make_synthetic_fixtures.py`; real replays are anonymized (`TestPlayer`) and credited in `tests/fixtures/ATTRIBUTION.md`.
- **The index is a projection, never a source of truth.** Deleting `out/index.sqlite` loses nothing; annotations and critiques are the only authored data and they live in sidecar files under `out/`. `replay_md5` is the replay's internal hash, not the `.osr` file's md5 (verified: no matches over 383 replays), so a historical `replay_path` needs an explicit parse pass; `beatmaps.map_path` is the resolvable map file. `is_relax` means RX **or** AP **or** `aim_mode.is_relax`.
- Git: push to `main`; the release workflow runs on tags.
- The blacklist × on a `/maps` card is a sibling `<form>`, never inside the `<a>` (invalid markup); on a phone it is centred and the card body reserves its width, or it eats the title.
The web layer's traps: `render()` must pass `status_code=` (a 404 otherwise renders 200); the listing reads `rank_status`, not `status`; the trust banner's wording must differ, not just its class; cover fetches are lazy per `<img>` so a listing render never makes 792 HTTP requests. "Open in osu!" posts the md5 to `/open` and the **server** runs `gio open osu://b/<id>` (`_game_uri` builds the URI from the index, never from the form; `_launch_uri` is module-level so it can be patched). Raw `osu://` links stay on the map page only: Firefox-based browsers refuse unknown schemes without `network.protocol-handler.external.<scheme>=true`, so a client-side link opens a dead tab, and a phone has no handler.
The nav has six links now and must wrap below 620 px (it silently widened the document to 401 px at 320 when it had five). A widget partial that does not exist for an id in `dashboard.WIDGETS` is a 500 at render time, not at import.
